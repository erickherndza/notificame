2) FORMATO DE FRAME (función generateCommand, código fuente real)
======================================================================

    byte[0] = 0x00                  (constante)
    byte[1] = CMD                   (opcode, ver tabla abajo)
    byte[2] = 0x01                  (constante en todas las llamadas del SDK)
    byte[3] = 0x00                  (constante)
    byte[4] = LEN                   (longitud de lo que sigue: 1 + payload.length)
    byte[5] = SUBTYPE               (0=GET/query, 1=SET/config, en la mayoría
                                      de los comandos; en otros es un
                                      sub-parámetro específico, ver tabla)
    byte[6..] = payload             (datos específicos del comando)

negativos (ej: DEVICE_BIND = -127 en Java == 0x81 == 129 sin signo).

Cada uno tiene su función correspondiente en UWatchBleManager.java con el
byte exacto que se debe mandar — por ejemplo:

  GET_BATTERY:        generateCommand(GET_BATTERY, (byte)1, (byte)0)
  FIND_DEVICE (start): generateCommand(FIND_DEVICE, (byte)1, (byte)0)
  FIND_DEVICE (stop):  generateCommand(FIND_DEVICE, (byte)1, (byte)1)
  MUSIC_CONTROL:       generateCommand(MUSIC_CONTROL, (byte)1, <MusicControl.PLAY/PAUSE/...>)

======================================================================
5) SIGUIENTE PASO — construir un cliente propio
======================================================================
Con esto ya se puede escribir un script Python (bleak) que:
  1. Conecte al TB39 (ya lo hace scan_watch.py)
  2. Habilite notify en 0xFF14 (ya lo hace sniff_watch.py)
  3. Arme frames con UWatchCommandConst.generateCommand() traducido a Python
  4. Mande GET_BATTERY, SYNC_TIME, FIND_DEVICE, etc. y lea las respuestas
     reales por notify — ahora sí sabremos exactamente qué decodificar en
     cada respuesta, porque conocemos los opcodes de pregunta.
